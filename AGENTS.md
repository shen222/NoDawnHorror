# Project change reporting

Keep `PROJECT_REPORT.md` updated when completing work in this project, across project chats.

- Record completed bug fixes, new features, and meaningful improvements.
- Use the date in Asia/Tokyo and describe the user-visible result in plain language.
- Include affected files and verification when known. Clearly identify anything unverified.
- Record only changes supported by the chat or inspected project files; do not invent earlier history or treat planned work as completed.
- Append to the existing history. Avoid duplicate entries for the same change.
- Update the report before the final response when a task changes the project.
